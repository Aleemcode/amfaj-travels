# Architecture SOP - Website Planning and Build

## Purpose

Define the website planning and build workflow for AMFAJ Travels and Tours.

## Primary Website Job

Convert interested visitors from Instagram, Facebook, TikTok, WhatsApp Status, referrals, and ads into qualified WhatsApp leads.

## Inputs

- Approved brand schema from `gemini.md`.
- Launch strategy.
- Lead funnel map.
- Approved website copy.
- Brand assets.
- WhatsApp link.
- Hosting and domain decisions.

## MVP Pages

- Home.
- Packages.
- Umrah Packages.
- Hajj Packages.
- Guidance.
- Umrah Guidance.
- Hajj Guidance.
- FAQ.
- Contact.
- Privacy Policy.
- Terms and Conditions.

## Site Architecture Source

The canonical website information architecture is `website_information_architecture.md`.

Any change to page hierarchy, URL structure, header navigation, footer navigation, breadcrumb logic, or internal linking should be recorded there before implementation.

## Design Source

The canonical visual and interaction direction is `design.md`.

Use `design.md` for hero behavior, package card patterns, motion philosophy, CTA behavior, and component direction. Do not copy external reference assets or code.

## Required Checks Before Publishing

- CTA links work.
- Mobile layout works.
- No unverified price, visa, flight, or travel date claims.
- No worship acceptance guarantee.
- Religious positioning matches `gemini.md`.
- Contact details are correct.
- Analytics is installed if approved.

## Lead Capture Rule

The MVP website should use WhatsApp as the primary lead capture path. Forms and Google Sheets integration may be added later after the team approves fields and follow-up workflow.

## Change Rule

If website logic, sitemap, CTA flow, or claim policy changes, update this SOP and `gemini.md` before implementation.
